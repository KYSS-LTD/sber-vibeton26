# Локальная модель помощника

## Что используется

Контейнер `ollama` (образ закреплён по digest в `compose.yaml`) и модель `qwen3:0.6b`. Её digest записан в [backend/llm-model.json](../backend/llm-model.json); init-контейнер `llm-init` скачивает модель, сверяет digest и отказывается продолжать при несовпадении. Затем он делает пробный запрос через тот же `ModelGateway`, что и помощник, чтобы первая настоящая просьба не ждала прогрева.

Веса хранятся в томе `ollama` и переживают перезапуск. Повторный `docker compose up` их не скачивает.

## Запуск

Нужны Docker с Compose, около 12 ГБ памяти на всю систему и доступ в интернет **один раз** — для скачивания модели (около 0,5 ГБ).

```bash
cp .env.example .env
docker compose up --build -d
docker compose logs -f llm-init
```

Готовность: `llm-init` завершился с кодом 0.

```bash
docker compose ps -a llm-init
docker compose exec ollama ollama list
```

В списке должна быть `qwen3:0.6b`. Холодный первый запрос на GPU может идти около 44 секунд из-за компиляции CUDA; прогрев в `llm-init` делает это заранее.

С NVIDIA GPU скопировать `compose.gpu.yaml` в `compose.override.yaml` до запуска (подробности — в [README](../README.md)).

## Проверка работы

1. Войти администратором, открыть «Управление» → «Провайдер помощника», выбрать «Локально · Ollama / Qwen3 0.6B».
2. Открыть «Помощник», задать вопрос, например «Сколько сотрудников сейчас на объекте?».
3. В ответе указаны провайдер и вызванные инструменты; каждая строка ответа — готовый факт из БД. Те же числа можно сверить на вкладке «Обзор объекта».
4. Автоматически: `docker compose --profile test run --rm tests` (файл `test_llm_gateway.py`) и сценарий помощника в `browser-tests`.

Каждый запрос записывается в таблицу `llm_requests` (провайдер, инструменты, факты, ответ или код ошибки).

## Как модель встроена

Два вызова с температурой 0 и принудительной JSON-схемой ([prompts/tools.json](../backend/prompts/tools.json)):

1. Вопрос → список инструментов из пяти разрешённых (`onsite_now`, `shift_statistics`, `zone_statistics`, `passage_denials`, `period_summary`).
2. Сервер выполняет параметризованные SQL через роль `prohod_analytics` (только чтение, таймаут 5 секунд), объект и период задаёт он сам, затем формирует факты с номерами.
3. Факты → список номеров, которые войдут в ответ. Текст ответа собирает сервер из выбранных фактов.

Модель не видит БД и не пишет SQL или числа. Выбор неизвестного инструмента или номера отклоняется, пользователь видит ошибку.

## Офлайн-развёртывание

Один раз запустить систему с интернетом, затем перенести том:

```bash
docker run --rm -v prohod_ollama:/from -v "$PWD":/to alpine tar czf /to/ollama-volume.tgz -C /from .
# на другой машине, до первого запуска проекта prohod:
docker volume create prohod_ollama
docker run --rm -v prohod_ollama:/to -v "$PWD":/from alpine tar xzf /from/ollama-volume.tgz -C /to
```

После этого `llm-init` найдёт модель локально, сверит digest и не будет обращаться к реестру. Проверить имя тома можно командой `docker volume ls`. Вместо `alpine` подойдёт любой образ с `tar`, уже загруженный на целевой машине (образы системы можно перенести через `docker save` / `docker load`).

## Замена модели

1. Скачать новую модель в Ollama и узнать её digest.
2. Записать имя и digest в `backend/llm-model.json`.
3. Заменить имя модели в `ModelGateway.complete` ([llm.py](../backend/app/llm.py)): оно пока задано там отдельной строкой.
4. Заново выполнить тесты помощника и сравнить выбор инструментов на типичных вопросах: более крупные модели обычно выбирают инструменты точнее, но требуют больше памяти.

## Внешний провайдер GigaChat

1. В `.env` задать `GIGACHAT_AUTH_KEY` (ключ авторизации), `GIGACHAT_SCOPE` (`GIGACHAT_API_PERS` по умолчанию) и `GIGACHAT_CA_FILE=/certificates/russian_trusted_ca_bundle.pem`. Файл сертификатов лежит в репозитории в `infra/ca/`; корневые сертификаты общедоступны. Проверка TLS не отключается.
2. `docker compose up -d backend`.
3. В «Управление» выбрать «Внешний сервис · GigaChat» и повторить вопрос. Ошибка провайдера показывается явно, переключения на локальную модель втихомолку нет.

## Неполадки

| Симптом | Причина и действие |
|---|---|
| `llm-init` перезапускается | Нет интернета или реестр недоступен: повторить позже или перенести том |
| `Ollama model digest changed` | Реестр отдал другую модель: проверить `llm-model.json`, не обновлять вслепую |
| Помощник отвечает 502 | Провайдер недоступен или вернул неподтверждённый ответ: смотреть `docker compose logs backend`, поле `error` в `llm_requests` |
| Ответ не по теме | Маленькая модель выбрала не тот инструмент: переформулировать вопрос или использовать более крупную модель |
