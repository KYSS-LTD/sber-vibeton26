# Фактические результаты проверки — 10 октября 2026

Полный `docker compose up --build -d` выполнен на предоставленном Linux-сервере. Система доступна на `https://kyssltd.ru`; API и PostgreSQL healthy, остальные постоянные сервисы работают. Сервер: Ubuntu 26.04.1, Docker 29.8.0, Compose 5.5.1, RTX 4090 24 ГБ. Подключение к GPU из контейнеров проверено.

До предоставления сервера проверки выполнялись на Windows с настоящими сервисами PostgreSQL 17.6 / PostGIS 3.6.2, SeaweedFS 4.48, Keycloak 26.4.7 и Ollama 0.12.3: там Docker Desktop/WSL потребовали прав администратора. Теперь интеграционные и браузерные тесты выполнены внутри того же Docker Compose, в котором работает приложение.

Зависимости runtime и экспорта фиксируются отдельно. Образы Compose закреплены по digest; Qwen — по digest manifest. В репозиторий не входят локальные пароли, тестовые базы, фотографии, скачанные модели и инструменты.

Не выполнены ручные испытания сотрудников с камерой/телефоном, физической распечатки перед камерой, фонового GPS/доверия HTTPS на телефоне; не измерены FAR/FRR. Реальный GigaChat ожидает ключ. Полная матрица ручных испытаний — [acceptance.md](acceptance.md).

На сервере сохранены `api-tests.log`, `browser-tests.log`, `face-check.log`, `persistence-restart.log`, `persistence-backup.log`, `restored-final-tests.log`. Резервные копии лежат в закрытом каталоге `backups/`; тестовые контейнеры остановлены, рабочий проект `prohod` продолжает работать.

Неподвижный цифровой снимок в той проверке получил высокий PAD score и был остановлен только поворотами головы. Одна MiniFASNet не даёт абсолютной гарантии, это ограничение учтено ниже.

## Состояние после перехода на проверку только анфас

Решение команды от 10 октября: на КПП сотрудник смотрит прямо в камеру, повороты головы не требуются (см. [decisions.md](decisions.md), п. 5). Таблица выше получена до этого изменения, поэтому её строки про 29 тестов API и 7 сценариев Playwright относятся к прежней версии.
