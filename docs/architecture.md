# Архитектура и правила

## Доступ

Keycloak выдаёт JWT RS256 с issuer публичного HTTPS-адреса, audience `prohod-api` и сроком жизни 120 секунд. API проверяет подпись, issuer, audience и время; неизвестный/заблокированный principal отклоняется. В браузере токен находится в памяти Keycloak adapter. Пароли не хранятся в приложении.

Прикладная БД хранит назначения. Вахтёр имеет одно действующее назначение; операция прохода всегда проверяет его независимо от дополнительных ролей. Руководитель имеет назначения на несколько объектов, администратор — глобальный доступ. Все вызовы API, события, файлы и аналитика проверяют роль и объект.

`app.actor` и `app.roles` задаются API через `SET LOCAL` в транзакции. Клиент/модель не задают их самостоятельно. RLS включён на прикладных таблицах, runtime-пользователи не владельцы, не superuser, не BYPASSRLS. `SECURITY DEFINER` используется только для узких функций проверки назначений и очереди уведомлений с фиксированным search_path. В БД нет публичного SQL endpoint. Read-only подключение аналитики дополнительно имеет SELECT только на необходимых таблицах и statement timeout 5 секунд.

## Данные

Источник схемы: `backend/sql/001_schema.sql`, таблица применённых миграций `schema_migrations`. Файл одновременно служит SQL-снимком первой версии. Последующие изменения добавляются новыми миграциями, первая после запуска не переписывается.

- `principals -> employees`, `principals/sites -> site_memberships` и `controller_assignments`.
- `employees -> face_reference_sets -> face_reference_photos -> face_templates`; снимки ссылаются на `media_objects`.
- `employees/sites -> daily_qr_credentials`; `principals/checkpoints -> gate_sessions`.
- `passage_attempts` связывает QR, сессию, эталоны и браузерный ключ. `device_confirmations` уникален по попытке.
- `shifts` содержит entry/exit attempts и уникальную открытую смену сотрудника; `location_checks` относится к конкретной смене.
- `site_map_versions -> zone_shapes`, `zones` сохраняет идентичность зоны по объекту и названию. Точка сохраняет использованную версию формы зоны.
- `alerts -> notifications`; фоновые задания доставляют уведомления без расширения прав сотрудника.

Эталоны публикуются атомарно. Deferred constraint требует ровно три шаблона у активного набора. Исторические наборы и версии зон сохраняются.

## Проход

1. Суточный QR — 256-битный случайный токен. В БД хранится SHA-256 и зашифрованная копия для повторного отображения. Срок — полночь часового пояса объекта.
2. Вахтёр сканирует токен; сервер определяет employee/site и проверяет назначение и состояние смены.
3. Новая попытка имеет уникальный nonce, 30 секунд, конкретную версию эталонов/ключа и случайный порядок двух поворотов.
4. Видимая страница сотрудника подписывает точные серверные байты ECDSA P-256/SHA-256, только если показывает тот же QR. Подпись связывает employee, site, checkpoint, direction и попытку.
5. Камера передаёт 24 кадра примерно за 8 секунд. YOLO-face обнаруживает лицо, YuNet даёт пять ориентиров; SFace сравнивает с тремя эталонами по правилу 2/3. MiniFASNet оценивает живость, ориентиры проверяют случайный порядок поворотов.
6. При ошибке или 15 секундах ожидания YOLO используется YuNet; неверная личность/живость не вызывает ослабление проверки.
7. Финализация блокирует сотрудника и попытку, повторно проверяет права, срок, назначения, QR, ключ и эталоны. Запись shift и результата — одна транзакция. Повтор финализации возвращает ранее сохранённый результат.

Локальные модели/исходные ревизии и SHA-256 находятся в `backend/models.json`. Init конвертирует YOLO и MiniFASNet в ONNX, runtime не требует PyTorch/GPU. `models/installed.json` фиксирует контрольные суммы итоговых ONNX. Лицензии моделей должны сопровождать распространяемую сборку; сведения — исходные репозитории в manifest и README.

## GPS и аналитика

Клиент не вызывает Geolocation до открытия смены. После входа — одно измерение и интервал 600 секунд; закрытие отменяет интервал и fetch. API блокирует строку смены и отклоняет закрытую смену, чужого сотрудника, старое/будущее измерение и слишком частые сообщения. sample_id обеспечивает идемпотентность. Большая погрешность и нереалистичная скорость помечаются подозрительными, но это не доказательство отсутствия GPS spoofing.

Источником времени аналитики является серверное received_at. Каждая допустимая точка удерживается до следующей, но максимум 600 секунд; интервал обрезается закрытием смены, текущим временем и выбранным периодом. Отсутствие точек не заполняется. Heatmap показывает оценочные человеко-минуты, а не непрерывное присутствие. Подозрительные точки исключаются; отсутствие наблюдений визуально отделено от малого значения.

Привязка схемы — линейное преобразование прямоугольника изображения по west/east/south/north, WGS84. Зоны рисуются точками, сервер проверяет геометрию, включение в объект и отсутствие пересечений. Пунктирный маршрут только соединяет измерения.

## S3

S3, filer, master и PostgreSQL не публикуют порты хоста. API работает без административных S3-ключей. Provisioner/storage-worker имеет отдельный bootstrap-том; создаёт private buckets, IAM identities и политики на точные bucket/prefix/action. GetObject/PutObject разделены; DeleteObject/DeleteBucket/PutBucketPolicy запрещены сервисным ключам. SeaweedFS 4.48 переводит разрешение записи в базовое Write и не принимает Deny в PutUserPolicy: поэтому запрет удаления дополнительно обеспечивается bucket policy. Эти ограничения проверены реальными запросами. В браузере нет S3 credentials и публичных ссылок.

Секреты scope шифруются Fernet ключом runtime-тома. API выбирает сервисный scope после проверки роли/объекта и отдаёт файл по media_id. Bootstrap identity записывается в динамическое IAM-хранилище filer до добавления остальных пользователей, чтобы environment fallback не исчез при первом IAM update.

PostgreSQL, Keycloak и S3 получают отдельные тома с необходимыми им файлами. В этих томах файлы читаются непривилегированными пользователями контейнеров; доступ ограничивает само подключение тома. Полный bootstrap-том остаётся у инициализации, настройки хранилищ и тестовых сервисов. Миграции получают отдельный том с паролем owner и начальными аккаунтами. Производные тома пересоздаются из bootstrap при восстановлении.

## Помощник

Единственный слой inference — `app.llm.ModelGateway`. Первый вызов выбирает 1–5 инструментов из allowlist. Сервер задаёт объект и период, выполняет параметризованные SQL через read-only роль и строит факты. Второй вызов выбирает факты для короткой сводки. Неизвестные инструменты/идентификаторы отклоняются; числа и предложения формирует сервер из результатов БД. Ошибка провайдера не приводит к незаметному переключению.

Prompts/schema находятся в `backend/prompts`. Запись LLM-запроса содержит actor, site, provider, инструменты, факты, ответ или код ошибки; ключи/пароли туда не попадают.

## Решения и границы

Полный журнал решений с вариантами и последствиями — [decisions.md](decisions.md); схема компонентов и последовательность прохода — [solution-scheme.md](solution-scheme.md). Краткий перечень:

1. Один адаптивный сайт вместо нативных приложений; потерю фонового GPS показываем явно.
2. Отдельный Keycloak вместо второй реализации паролей; объектные назначения — в бизнес-БД.
3. Суточный QR — указатель сотрудника, одноразовая попытка — единица подтверждения прохода.
4. Три эталона и SFace для идентичности; YOLO выполняет обнаружение, не определение личности.
5. SeaweedFS и реальные IAM-политики вместо общих S3-ключей во frontend.
6. LLM выбирает SQL-инструменты и факты; произвольный SQL/непроверяемые цифры не принимаются.

Код и документация подготовлены с помощью Codex и проверены с помощью Claude Code; качество подтверждается перечисленными автоматическими/ручными проверками, а не самим фактом генерации. Подробности — [ai-usage.md](ai-usage.md).
