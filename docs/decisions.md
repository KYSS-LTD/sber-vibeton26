# Журнал решений

Каждая запись: что решили, какие были варианты, чем пожертвовали и где это в коде. Новые решения добавлять в конец, старые не переписывать — менять статус на «пересмотрено» со ссылкой на новую запись.

## 1. Один адаптивный сайт вместо нативных приложений

- **Решение.** Проходная, телефон сотрудника и администратор — один Next.js-сайт; интерфейс выбирается по роли ([page.tsx](../frontend/app/page.tsx)).
- **Варианты.** Нативные приложения; PWA-обёртка. Отвергнуты: сборка и установка на телефоны судей дороже, чем открыть ссылку.
- **Цена.** Браузер не гарантирует GPS с выключенным экраном; потерю связи показываем явно (неизвестная позиция после 12 минут).

## 2. Keycloak для паролей, права на объекты — в бизнес-БД

- **Решение.** Пароли и токены ведёт Keycloak (JWT RS256, срок 120 секунд, проверка issuer, audience, подписи). Роли и назначения на объекты хранит PostgreSQL ([auth.py](../backend/app/auth.py)).
- **Варианты.** Собственная таблица паролей. Отвергнуто: вторая реализация парольной защиты — лишний риск.
- **Цена.** Ручное добавление пользователя в Keycloak не создаёт запись в БД; пользователей заводят через «Управление».

## 3. Проход: суточный QR + одноразовая попытка + подпись телефона + лицо

- **Решение.** Суточный QR только указывает на сотрудника. Каждый проход — новая серверная попытка с nonce на 30 секунд. Телефон подписывает её ключом ECDSA P-256, который не извлекается из браузера (IndexedDB). Подпись связывает сотрудника, объект, КПП, направление и попытку ([security.py](../backend/app/security.py), [passages.py](../backend/app/passages.py)).
- **Почему так.** Скопированный QR сам по себе ничего не даёт: без телефона с зарегистрированным ключом и без совпавшего лица проход не открывается (требование Д10, основание для снятия №3).
- **Цена.** Ключ программный, не аппаратная аттестация; передача разблокированного телефона владельцем остаётся ограничением.

## 4. Идентификация: три эталона, SFace, два детектора

- **Решение.** Три эталонных снимка на сотрудника, SFace считает сходство, YOLO-face и YuNet находят лицо, MiniFASNet оценивает живость. Засчитывается лучший из трёх эталонов, итог — медиана по хорошим кадрам, нужно не меньше трёх хороших кадров из 16 ([vision.py](../backend/app/vision.py)).
- **Почему лучший из трёх.** Эталоны не обязаны быть строго фронтальными; требовать совпадения с двумя из трёх стало бы ложными отказами.
- **Цена.** Порог 0,45 для SFace и 0,8 для PAD — стартовые значения, не измеренные на реальных людях ([limitations.md](limitations.md)).

## 5. Проверка только анфас (10 октября 2026)

- **Решение.** Случайные повороты головы убраны; сотрудник смотрит прямо в камеру 4 секунды. В кадре может быть несколько лиц: проверяется самое крупное.
- **Что потеряно.** Проверка поворотов головы отсекала неподвижный цифровой снимок. Теперь защита от подмены держится на MiniFASNet и на подписи телефона.
- **Что делаем взамен.** Честно фиксируем это в ограничениях и документах приёмки; замер на фото с экрана и распечатке — в планах ([limitations.md](limitations.md)). Повороты головы без решения команды не возвращаем.

## 6. Права в самой БД: RLS и роли без обхода

- **Решение.** На прикладных таблицах включён RLS; API перед каждой транзакцией задаёт `app.actor` и `app.roles` через `SET LOCAL`. Роли `prohod_app` и `prohod_analytics` не владельцы, не superuser, без BYPASSRLS, DELETE не выдан, аудит доступен только на запись и чтение ([001_schema.sql](../backend/sql/001_schema.sql)).
- **Почему.** Ошибка в одном обработчике не должна открывать данные чужого объекта.

## 7. Хранилище файлов: приватный SeaweedFS с политиками

- **Решение.** Эталоны, кадры-доказательства, планы и отчёты лежат в приватных бакетах SeaweedFS; сервисные ключи разделены по префиксам и действиям, удаление запрещено; в браузере нет S3-ключей и публичных ссылок ([storage.py](../backend/app/storage.py)).
- **Цена.** Ограничения SeaweedFS 4.48 обходятся политикой бакета; поведение проверено реальными запросами.

## 8. Помощник: модель выбирает инструменты, цифры формирует сервер

- **Решение.** Первый вызов модели выбирает 1–5 инструментов из белого списка. Сервер сам выполняет параметризованные SQL через read-only роль и строит нумерованные факты. Второй вызов выбирает номера фактов. Текст ответа собирается из фактов на сервере ([llm.py](../backend/app/llm.py)).
- **Почему.** Модель не пишет SQL и не пишет числа, поэтому выдумать цифру она не может (основание для снятия №6). Неизвестный инструмент или номер факта отклоняется, ошибка провайдера не приводит к тихому переключению на другого.
- **Цена.** Помощник отвечает только про пять поддерживаемых тем; произвольные вопросы не поддерживаются.

## 9. Два провайдера модели

- **Решение.** По умолчанию локальный Ollama с Qwen3 0.6B (digest закреплён в `backend/llm-model.json`), внешний — GigaChat. Провайдер переключает администратор в интерфейсе ([local-model.md](local-model.md)).
- **Почему маленькая модель.** Работает на CPU у любого судьи; задача модели узкая (выбор из пяти инструментов в заданной JSON-схеме).

## 10. Геопозиция: только во время смены, раз в 10 минут

- **Решение.** Браузер не обращается к Geolocation до открытия смены. После входа одно измерение, затем интервал 600 секунд. Сервер отклоняет запросы по закрытой смене, чужим сотрудникам и слишком частые.
- **Аналитика.** Точка действует до следующей, но не дольше 600 секунд; пропуски не достраиваются. Подозрительные точки исключаются из heatmap. Heatmap показывает оценку человеко-минут, а не непрерывное присутствие.

## 11. Развёртывание: Docker Compose с закреплёнными образами

- **Решение.** Все образы закреплены по digest, зависимости — lock-файлами, модели — по SHA-256. Локально HTTPS даёт Caddy с внутренним CA; на сервере — системный Caddy с Let's Encrypt. GPU подключается файлом `compose.gpu.yaml`, без него всё работает на CPU.
- **Резервные копии.** Скрипты `scripts/backup.*` и `scripts/restore.*`; восстановление проверено в отдельном проекте ([deployment.md](deployment.md)).

## 12. Уведомления: SSE и Web Push

- **Решение.** Телефон получает попытки прохода и события через SSE (`/api/v1/me/events`), оповещения руководителю — через Web Push (VAPID). Фоновый воркер ищет потерю геопозиции, напоминает о смене за 15 минут и доставляет уведомления.
