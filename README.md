# Проход

Веб-система КПП и присутствия на строительных объектах. FastAPI, Next.js, PostgreSQL/PostGIS, Keycloak, приватный SeaweedFS S3, локальная биометрия и два провайдера помощника.

## Запуск

Требуются Docker Engine с Compose на Linux либо Docker Desktop с WSL2 на Windows, 12 ГБ доступной памяти, около 15 ГБ места и интернет для первой загрузки моделей. На Windows первоначальная установка WSL/Docker может потребовать администратора и перезагрузки.

```powershell
Copy-Item .env.example .env
docker compose up --build -d
docker compose logs -f model-init llm-init backend
```

Открыть https://localhost. Первое создание моделей ONNX и загрузка Qwen занимают несколько минут. Сервисы и секреты сохраняются в именованных томах; повторный запуск не меняет пароли и не скачивает проверенные модели заново.

Для NVIDIA GPU с установленным NVIDIA Container Toolkit скопировать `compose.gpu.yaml` в `compose.override.yaml`. После этого обычная команда `docker compose up --build -d` автоматически подключает GPU для Ollama и YOLO/MiniFASNet. Отдельный CUDA runtime закреплён в `backend/requirements-gpu.lock`; SFace и YuNet работают на CPU. Если выбран CUDA и provider не загрузился, биометрия возвращает ошибку. Без override обычный Compose работает на CPU.

Запуск на сервере Linux, SSH и резервное копирование — [docs/deployment.md](docs/deployment.md).

Для телефона задать в `.env` `APP_HOST` равным LAN-IP компьютера и `PUBLIC_ORIGIN=https://<LAN-IP>`. Сделать это **до первого запуска**: адрес является issuer Keycloak. Телефон должен находиться в той же сети. Открыть порт 443 в Windows Firewall при необходимости.

```powershell
docker compose cp proxy:/data/caddy/pki/authorities/local/root.crt ./prohod-root.crt
```

Установить этот корневой сертификат как доверенный на компьютере и телефоне. На iOS включить полное доверие установленному корневому сертификату. Обход предупреждения HTTPS не всегда включает доступ к камере/GPS.

Случайные пароли начальных пользователей доступны локальному владельцу Docker:

```powershell
docker compose run --rm --no-deps --entrypoint cat secrets /bootstrap/accounts.json
```

Начальные логины: `admin`, `manager`, `guard-a`, `guard-b`, `worker-a`, `worker-b`. Объекты А/Б и их границы являются демонстрационными; реальные координаты следует настроить через API/интерфейс. Лиц и координат сотрудников в демонстрационные данные не подмешивается.

1. Войти администратором; создать сотрудников или использовать демонстрационных.
2. Назначить сотрудника на объект и опубликовать **три** разных снимка его лица.
3. Сотрудник входит на своём телефоне: браузерный ключ регистрируется автоматически, появляется суточный QR.
4. Вахтёр своего объекта открывает «Проходная», включает камеру и выбирает вход/выход.
5. Сканирует QR; сотрудник 4 секунды смотрит прямо в камеру (поворачивать голову не нужно). Телефон продолжает показывать QR.
6. Руководитель/администратор открывает карту, редактор зон, heatmap и помощника.

Keycloak administration: `/auth/admin/`. Bootstrap login `kcadmin`; его отдельный пароль хранится в томе bootstrap в файле `kc_admin`. Прикладные роли и назначения изменяются через систему; добавление аккаунта вручную в Keycloak само по себе не регистрирует его в прикладной БД.

## Провайдеры LLM

По умолчанию Ollama `qwen3:0.6b`; digest фиксируется в `backend/llm-model.json` и проверяется init-контейнером. Для GigaChat задать `GIGACHAT_AUTH_KEY` и `GIGACHAT_SCOPE` в `.env`, перезапустить backend. Набор публичных корневых сертификатов лежит в `infra/ca/` и уже указан в `.env.example` (`GIGACHAT_CA_FILE=/certificates/russian_trusted_ca_bundle.pem`); для другого центра положить свой PEM рядом и изменить путь. Проверка TLS никогда не отключается. Провайдер выбирается администратором в «Управление», затем проверяется через «Помощник».

Модель выбирает инструменты; SQL задаёт сервер. Сводка состоит из фактов, полученных из БД, с проверенными идентификаторами. Пошаговая инструкция по локальной модели (запуск, проверка, офлайн, замена) — [docs/local-model.md](docs/local-model.md); шаблоны — `backend/prompts`.

## Проверка

```powershell
docker compose --profile test run --rm tests
docker compose --profile test run --rm browser-tests
```

Интеграционные SQL-тесты используют настоящую БД, отдельные тестовые записи и откатывают транзакции. S3-тест намеренно оставляет небольшой объект `evidence/tests/` для проверки запрета удаления. Авторизованные браузерные тесты создают отдельного сотрудника `e2e-*` и тестовую зону: запускать на тестовой установке. Для сценария помощника дождаться успешного завершения `llm-init`. Ручная матрица проверки камеры, телефона и живости — `docs/acceptance.md`, фактические результаты — `docs/testing.md`.

`GET /api/v1/health` — готовность API; `/api/docs` — интерактивная документация, `/api/v1/openapi.json` — схема OpenAPI.

## Карты

Границы объекта, зоны и позиции сотрудников отображаются на [Leaflet](https://leafletjs.com/) поверх карты [OpenStreetMap](https://www.openstreetmap.org/): библиотека входит в сборку frontend, ключи и регистрация не нужны, backend карту не выдаёт.

- «Управление» → «Участок на карте»: администратор обводит границу объекта вершинами, перетаскивает их и сохраняет.
- «Схема и зоны»: руководитель делит объект на зоны; новые вершины притягиваются к вершинам границы и соседних зон.
- «Обзор объекта» и «Heatmap посещений»: последние позиции сотрудников, зоны и маршруты. Маркеры обновляются из БД каждые 10 секунд; кнопка «Где я» центрирует карту на устройстве.

Позиции сотрудников рисуются в браузере; OpenStreetMap получает только запросы тайлов с областью просмотра. Публичный `tile.openstreetmap.org` рассчитан на умеренную нагрузку ([политика](https://operations.osmfoundation.org/policies/tiles/)): для постоянной эксплуатации задайте собственный тайл-сервер, заменив `TILES` в `frontend/components/GeoMap.tsx`. Без доступа к тайлам границы, зоны и маркеры остаются на серой подложке.

## Данные и ограничения

GPS передаётся только при открытой смене, сразу после входа и затем раз в 10 минут. При закрытии таймеры/отправки прекращаются; сервер отклоняет опоздавшие пакеты. Потеря обновлений дольше 12 минут обозначается как неизвестная позиция. Браузер не гарантирует работу GPS в фоне и с выключенным экраном.

Суточный QR можно скопировать. Проход требует новой серверной попытки, подписи зарегистрированного браузера, совпадения лица и проверки живости. Браузерный ключ не является аппаратной аттестацией. Подменённый видеопоток, GPS spoofing и передача телефона владельцем остаются ограничениями веб-решения. Проверку «невозможно пройти за другого при любом нападении» система не заявляет.

Порог SFace `0.45` и PAD `0.8` — исходные настройки, не сертифицированные показатели качества. Перед эксплуатацией выполнить проверку на реальных сотрудниках/камерах; документировать ложные отказы и ложные допуски.

Резервное копирование и восстановление описаны в `docs/operations.md`. `docker compose down` сохраняет данные; `down -v` удаляет тома и не используется для обычного обновления.

Полный перечень ограничений, порядок измерения биометрии и планы — [docs/limitations.md](docs/limitations.md).
